= FPSOT data types specification

Rules for how FPSOT systems store and exchange data: text, dates and times, durations, time zones, numbers, money, identifiers, booleans, code values and coordinates.
Each type has one JSON form and one LinkML type.
Version 0.1 is a draft.

== Implement this spec

Read the normative text in `spec/en/` or `spec/fr/`.
Each requirement has an ID from `DAT-001` to `DAT-082`.
Import the LinkML types in `model/data-types.yaml` into your own model, and give each field the matching type.

== Adopt this spec

Read the guide in `docs/modules/en/pages/index.adoc` or `docs/modules/fr/pages/index.adoc`.
It shows a record modelled with these types and checked with the LinkML validator.
The comparison data in `jurisdictions/` shows how the rules of Canada and Québec differ.

== Layout

[cols="1,3"]
|===
| Folder | Content

| `spec/`
| Normative text, in English and French. `book.adoc` joins the pages into one book, published as PDF with each release.

| `docs/`
| Guides, in the Antora folder layout.

| `model/`
| The LinkML types and classes, with valid and invalid examples. Run `model/test-model.sh` after a change.

| `skill/`
| The agent skill: a short summary that cites requirement IDs.

| `rules/`
| Machine-checkable rules. None yet.

| `diagrams/`
| PlantUML sources and their rendered SVG files. None yet.

| `jurisdictions/`
| Comparison data: how each government handles the same topics.
|===
