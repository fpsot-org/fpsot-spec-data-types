= FPSOT data types specification
include::_fpsot-terms.adoc[]

This specification sets how {abbr-fpsot-first} systems store and exchange common kinds of data.
It covers text, dates, durations and time zones.
It also covers numbers and money, identifiers, code values and coordinates.
Each type has one {abbr-json-first} form and one LinkML type.
Two systems that follow it can then read each other's data without a conversion table.

The rules come in nine parts.

* xref:text.adoc[Text] sets the character encoding and the form of multilingual text.
* xref:dates.adoc[Dates and times] sets the form of instants, dates, local times and times of day.
* xref:durations.adoc[Durations and intervals] sets the form of a length of time and of a span between two points.
* xref:time-zones.adoc[Time zones] sets how to name a time zone and which database to use.
* xref:numbers.adoc[Numbers] sets when to use a {abbr-json} number and when to use a decimal string.
* xref:money.adoc[Money] sets the form of an amount and its currency, and how to round.
* xref:identifiers.adoc[Identifiers] sets the form of new identifiers and how to keep identifiers from other bodies.
* xref:codes.adoc[Booleans and code values] sets the form of yes-or-no values and of values from a fixed list.
* xref:geography.adoc[Coordinates] sets the form of points and shapes on the Earth.

== Related specifications

This specification builds on two other {abbr-fpsot} specifications.
The {abbr-fpsot} naming specification sets the case of field names and code values.
The {abbr-fpsot} internationalization specification sets the language tags.
It also sets how to display each type to people.
This specification sets only the stored and exchanged form.

== LinkML model

The file `model/data-types.yaml` defines each type and class of this specification in LinkML.
A model can import it and use its types as ranges.
Each page gives the LinkML type of each form.

== Conformance

[quote, 'link:https://www.rfc-editor.org/info/rfc8174[RFC 8174]']
____
The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 (link:https://www.rfc-editor.org/info/rfc2119[RFC 2119], link:https://www.rfc-editor.org/info/rfc8174[RFC 8174]) when, and only when, they appear in all capitals, as shown here.
____

The keywords follow requirement WRT-010 of the {abbr-fpsot} writing specification.
The French version uses the French keywords of WRT-011.

A system conforms to this specification when the data it stores and exchanges meets every MUST rule.
A data model conforms when every field it defines uses the form that this specification sets for its type.
